# SSD — Online Store (AI ver 2)

## 1. Краткое описание

Проект — одностраничное веб‑приложение магазина (SPA) на **Create React App**, с роутингом (**React Router**) и состоянием в **Redux Toolkit**. Пользователь может:

- просматривать каталог товаров,
- открывать страницу товара,
- добавлять товары в корзину (с ограничением по количеству),
- изменять количество / удалять позиции,
- применять промокод на странице корзины.

На текущем этапе данные каталога — локальные (константа `PRODUCTS`), бэкенд не подключён.

## 2. Цели и ограничения

### 2.1 Цели

- Быстрый интерактивный UI каталога/товара/корзины.
- Предсказуемая модель состояния (Redux) для корзины и уведомлений.
- Простая база для дальнейшего подключения API и оформления заказа.

### 2.2 Не цели (сейчас)

- Авторизация и личный кабинет.
- Реальные платежи/доставка/заказы на сервере.
- Поиск/фильтрация/сортировка, админ‑панель.

## 3. Технологии

- **React 19**
- **React Router DOM 7**
- **Redux 5 + React Redux 9**
- **Redux Toolkit 2** (reducers/actions, `configureStore`)
- **Reselect 5** (в зависимостях; в текущем коде может не использоваться)
- **CRA / react-scripts 5**

## 4. Структура проекта (ключевое)

- `src/App.js` — корневой компонент: `Provider`, `BrowserRouter`, маршруты.
- `src/page/*` — страницы:
  - `CatalogPage.js` — список товаров
  - `ProductPage.js` — карточка товара по `:id`
  - `CartPage.js` — корзина + промокод
- `src/components/*` — переиспользуемые компоненты (хедер, карточки, кнопки, уведомления).
- `src/store/*` — Redux store, reducers, actions, hooks.
- `src/const/*` — бизнес‑константы и утилиты форматирования.

## 5. Архитектура и потоки данных

### 5.1 Верхнеуровневая схема

UI (React компоненты/страницы) → dispatch(actions) → reducers (RTK) → state → selectors/hooks → UI

### 5.2 Роутинг

Определён в `src/App.js`:

- `/` → `CatalogPage`
- `/product/:id` → `ProductPage`
- `/cart` → `CartPage`

### 5.3 Управление состоянием

Store создаётся в `src/store/index.js` через `configureStore({ reducer: rootReducer })`.

`rootReducer` включает 3 среза:

- **`products`**: массив товаров каталога (по умолчанию `PRODUCTS`)
- **`cart`**: массив позиций корзины
- **`notification`**: boolean‑флаг показа всплывающего уведомления

Доступ к данным осуществляется через кастомные хуки в `src/store/hooks.js` (обёртки над `useSelector`) и `useAppDispatch()`.

## 6. Модель данных (фактическая)

### 6.1 Product (товар каталога)

Источник: `src/const/products.js`.

Поля (по использованию в UI):

- `id: string`
- `title: string`
- `price: number` (рубли, целое)
- `discount?: number` (проценты, 0..100)
- `image: string` (URL)
- `description: string`

### 6.2 CartItem (позиция корзины)

Хранится в `state.cart` и формируется при добавлении товара:

- `id: string`
- поля товара (`title`, `price`, `discount`, `image`, `description`, …)
- `quantity: number`

## 7. Бизнес‑правила

### 7.1 Лимит количества в корзине

- Константа: `MAX_PRODUCT_QUANTITY = 2` (`src/const/cart.js`).
- При добавлении и увеличении количества применяется ограничение `min(quantity, MAX_PRODUCT_QUANTITY)`.
- Если лимит достигнут, показывается уведомление (`notification = true`) и автоскрывается через 2.5 сек.

### 7.2 Скидки

- Скидка товара — процент `discount`.
- Цена со скидкой: `getDiscountedPrice(price, discount)` (округление `Math.round`).
- Формат цены: `formatPrice(price)` → `ru-RU` + `₽`.

### 7.3 Промокод в корзине

В `CartPage.js`:

- промокод: `SALE10`
- скидка: 10% от суммы корзины (после товарных скидок)
- применяется только при корректном вводе, иначе показывается текст ошибки

## 8. Компоненты и ответственность

- `Header` — навигация + бейдж количества товаров в корзине.
- `CatalogPage` — рендер сетки `ProductCard` по `products`.
- `ProductCard` — краткая карточка товара + `AddCartButton`.
- `ProductPage` — подробная страница товара по `id` из URL.
- `AddCartButton` — добавление в корзину с учётом лимита.
- `CartPage` — таблица корзины, промокод, очистка корзины.
- `CartItem` — строка товара в корзине: +/- количество, удалить.
- `Notification` — уведомление о превышении лимита.

## 9. Ошибки и edge cases

- `ProductPage`: если `id` не найден в `products`, показывается “Товар не найден” и ссылка в каталог.
- `CartPage`: если корзина пуста — отдельное состояние “В корзине пока ничего нет”.
- Негативное/нулевое количество: редьюсер удаляет позицию из корзины при `quantity <= 0`.

## 10. Сборка, запуск, тесты

- Установка: `npm i`
- Dev: `npm start` (по умолчанию `http://localhost:3000`)
- Build: `npm run build`
- Tests: `npm test`

## 11. Деплой (текущий сценарий)

Приложение — статический фронтенд. Деплой возможен как:

- статические файлы `build/` на любой static hosting (Nginx, S3, Cloudflare Pages и т.п.),
- обязательно настроить **SPA fallback** (перенаправление на `index.html` для маршрутов `/product/:id`, `/cart`).

## 12. План расширения (рекомендуемая дорожная карта)

- **API для товаров**: заменить `PRODUCTS` на загрузку с сервера, добавить статусы `loading/error`.
- **Persist корзины**: сохранять `cart` в `localStorage` (и восстанавливать при старте).
- **Оформление заказа**: экран checkout, валидация, создание заказа через API.
- **Промокоды/скидки**: перенести на сервер и сделать правила конфигурируемыми.
- **Тесты**: покрыть редьюсеры (cart/notification) и критические UI‑сценарии.

## 13. Правила обновления SSD

### 13.1 Когда обновлять

Обновляй `docs/SSD.md` в том же PR/коммите, где меняется хотя бы один из пунктов:

- архитектура или потоки данных;
- структура папок и ответственность модулей;
- бизнес‑правила (лимиты, скидки, промокоды, расчёты);
- модель данных (поля, типы, источники данных);
- ключевые зависимости, версии, сценарии запуска/деплоя.

### 13.2 Как обновлять

- Сначала обнови фактическое поведение в коде, затем синхронизируй SSD.
- Пиши только подтверждённые факты о текущей реализации, без предположений.
- Для будущих задач используй раздел «План расширения», не смешивай его с текущей реализацией.
- Сохраняй структуру документа (разделы/подразделы), чтобы изменения было легко сравнивать в diff.

### 13.3 Если раздел стал неактуальным

- Если часть документа временно не соответствует коду, пометь её как `Неактуально` и укажи короткую причину.
- В этой же правке добавь целевое состояние или ссылку на задачу/PR, где будет восстановлена актуальность.
- Не удаляй критичные разделы без замены: вместо удаления сначала внеси актуальную формулировку.
- Перед релизом в `main` в SSD не должно оставаться непомеченных расхождений с кодом.

### 13.4 Мини‑чеклист перед merge

- Маршруты и страницы в SSD соответствуют `src/App.js` и `src/page/*`.
- Описание store и срезов соответствует `src/store/*`.
- Бизнес‑правила совпадают с текущими константами и редьюсерами.
- Команды запуска/сборки/тестов остаются рабочими.
